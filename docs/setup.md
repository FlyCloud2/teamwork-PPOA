# W2 setup and actual installation notes

Test machine: Windows, Intel Core i7-12700H (20 logical CPUs), Python 3.10.22.
The initial system Python was 3.12 and had no PyTorch. The baseline uses CPU
PyTorch 2.4.1, Gymnasium 0.29.1 and MuJoCo 3.1.6. The exact installed dependency
set is recorded in `requirements-lock.txt`; `env.txt` is generated by
`scripts/collect_env.py`. The old inline CUDA comments in `requirements.txt`
refer to the W1 reference machine; W2 uses its CPU installation instructions.

## Windows installation

Use an ASCII-only path for the virtual environment. The source checkout can
remain in a directory with Chinese characters.

```powershell
python -m pip install uv
python -m uv python install 3.10
python -m uv venv --python 3.10 C:\Users\Public\codex-envs\teamwork-ppoa-py310
$PpoPython = 'C:\Users\Public\codex-envs\teamwork-ppoa-py310\Scripts\python.exe'
python -m uv pip install --python $PpoPython -r requirements-lock.txt
& $PpoPython scripts/collect_env.py
& $PpoPython scripts/run.py --env HalfCheetah-v4 --seed 0 --smoke --threads 1
```

On a new machine, an ASCII checkout and `.venv` are also suitable. `uv` is only
an installer; it is not imported by the training pipeline. A normal Python 3.10
venv and `python -m pip install -r requirements-lock.txt` work as well.

## Failures actually encountered on 2026-11-15

1. The downloaded source folder had no `.git`. Fetched `origin/main` and attached
   the unchanged local files to that history, without replacing existing files.
2. With the virtual environment below the Chinese checkout path, MuJoCo 3.1.6
   failed to read `half_cheetah.xml` (`mjParseXML: resource not found`). Moving
   the **environment installation** to an ASCII path fixed it. The failed run
   remains indexed as `failed`; it is not baseline evidence.
3. Printing a failed child log on the GBK console raised `UnicodeEncodeError`.
   Child output is now UTF-8; diagnostic printing uses `backslashreplace` so an
   error report cannot hide the original training failure.
4. Creating `D:\codex-envs` was denied by the filesystem. The ASCII path under
   `C:\Users\Public` was writable. No existing environment was deleted.

## Full baseline and checks

```powershell
& $PpoPython -m unittest discover -s tests -v
& $PpoPython scripts/run_baseline.py --jobs 3 --threads 1
& $PpoPython scripts/verify_runs.py --baseline
& $PpoPython scripts/plot.py --baseline --out figures/w2_baseline.png
```

`--jobs 1` (default) runs sequentially; 2 or 3 overlap independent environment
processes. Each process gets the same explicit OMP/MKL thread count. CPU is the
baseline default; `--cuda true` is an explicit alternative and fails if CUDA
is unavailable. CUDA was not benchmarked here. No speed claim is made from
comparing concurrent and sequential runs.

Optional W&B/video flags require their own optional dependencies and are not
used in W2. The default baseline needs no display or rendering.
