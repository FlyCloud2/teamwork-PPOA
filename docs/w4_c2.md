# W4 / C2 —— 同一批数据重复几个 epoch，到底买到了什么（2026-11-27）

本文件只记录**由脚本从 `runs/*/progress.csv` 读出的数字**，不手填。生成方式见文末；
表里的每个单元格都能在 `logs/c2_summary.json` 和 `logs/paper_vs_ours.json` 里找到
对应的 run 目录。

## 1. 为什么要做这一条

论文把 K = 10 写进 Table 3 之后就没再动过它：Table 1 的 11 组设置扫的是 ε、β 和
d_targ，K 始终是 10。也就是说，"同一批 rollout 重复训练 10 个 epoch"是 PPO 的核心
默认做法之一，却从未被消融过。

C2 只改这一个因子，两个臂都用论文默认的裁剪目标（ε = 0.2）。问题不是"哪个更好看"，
而是：**在同样的环境步数预算下，把同一批数据多过几遍，能换来多少回报？代价是多少？**

## 2. 跑了什么

| | K = 1 | K = 10 |
|---|---|---|
| 代理目标 | `clip0.2`（ε = 0.2，论文默认） | 同左 |
| 每个 batch 的优化 | 32 个 minibatch × 1 个 epoch | 32 个 minibatch × 10 个 epoch（每个 epoch 重新打乱顺序） |
| 数据 | 同一份 2,048 步 rollout | 同一份 2,048 步 rollout |
| 环境 | HalfCheetah / Hopper / Walker2d | 同左 |
| 种子 | 0 / 1 / 2 | 同左 |
| 步数 | 1,000,000（489 次更新，末批 576 步） | 同左 |

规模：3 环境 × 3 种子 × 2 臂 = **18 次**，全部 `completed`，全部通过
`scripts/verify_runs.py --c2`（检查两个臂只差 `update_epochs`，环境、种子、线程、
依赖和平台一致）。

两个臂由**同一台机器**、同一依赖、同一预算产生。K = 10 臂**没有**复用 W3 的
`clip0.2`：那批来自另一台机器，换机器正是单因子对照最不能容忍的混淆（见
`docs/deviations.md` 的 W4 段）。为了让同一 variant 的两个 profile 在 `runs/` 里不
撞名，runner 用 `--label k1 / k10` 把它们写进 run_id；标签不传给训练器。

## 3. 结果

指标与 C1 完全相同：一个 run 最后十个已结束 episode 的训练回报均值，再对 3 个种子取
mean ± std。18 次 run 全部 `completed`，全部通过 `scripts/verify_runs.py --c2`。

| 环境 | K = 1 | K = 10 | Δ（K10 − K1） | 比值 | 胜者 |
|---|---:|---:|---:|---:|---|
| HalfCheetah-v4 | 772.7 ± 32.2 | 2247.8 ± 1411.8 | +1475.2 | 2.91× | K = 10 |
| Hopper-v4 | 1282.8 ± 156.8 | 1775.4 ± 389.7 | +492.5 | 1.38× | K = 10 |
| Walker2d-v4 | 1046.2 ± 436.0 | 3688.0 ± 856.6 | +2641.8 | 3.53× | K = 10 |

逐种子明细（每格：K = 1 / K = 10）：

| 环境 | seed 0 | seed 1 | seed 2 |
|---|---|---|---|
| HalfCheetah-v4 | 793.8 / 1421.2 | 735.7 / 1444.3 | 788.5 / 3878.0 |
| Hopper-v4 | 1455.8 / 2159.5 | 1242.8 / 1380.4 | 1149.9 / 1786.2 |
| Walker2d-v4 | 575.9 / 2775.8 | 1436.8 / 3813.1 | 1126.0 / 4475.2 |

K = 10 在 **3/3 环境**胜出；按同种子配对比较是 **9/9** 成立（每一对里 K = 10 都高于
同种子的 K = 1）。幅度从 +38%（Hopper）到 +250%（Walker2d）。

图：`figures/c2_epochs.png`（分组柱状图 + 种子散点）、`figures/c2_curves.png`（学习曲线）。

代价与诊断量（末 50 次更新的均值；墙钟为单个 run 的分钟数）：

| 环境 | clipfrac K=1 / K=10 | approx_kl K=1 / K=10 | 熵 K=1 / K=10 | 墙钟 min K=1 / K=10 |
|---|---:|---:|---:|---:|
| HalfCheetah-v4 | 0.000 / 0.056 | 0.00007 / 0.00725 | 7.9 / 2.2 | 20.0 / 29.5 |
| Hopper-v4 | 0.000 / 0.030 | 0.00004 / 0.00477 | 3.9 / 1.8 | 22.0 / 30.9 |
| Walker2d-v4 | 0.000 / 0.046 | 0.00006 / 0.00679 | 7.9 / 3.2 | 21.8 / 28.3 |

墙钟均值 21.3 → 29.5 分钟（**1.39 倍**），换来 1.38×–3.53× 的回报。

## 4. 怎么读这个结果

1. **直接答案**：在同样 1,000,000 环境步的预算下，K = 10 在三个环境都明显更好，
   且同种子配对 9/9 成立。在这套设置里，"同一批数据过 10 遍"不是可有可无的默认值，
   而是主要的性能来源之一。
2. **机制（这是推断，不是测量）**：K = 1 时每个 batch 只过一遍数据，策略移动很小 ——
   末 50 次更新的 `approx_kl` 只有 4×10⁻⁵～8×10⁻⁵，`clipfrac` 在**所有种子、所有环境
   都是 0.000**，熵几乎没降（HalfCheetah 与 Walker2d 的 7.9 接近初始 logstd）。也就是说：
   单 epoch 时裁剪机制基本没被触发，一个 rollout 的学习潜力没有被用掉。K = 10 时
   `approx_kl` 提高约 100 倍到 5×10⁻³～7×10⁻³（仍在论文 d_targ = 0.01 之下），
   `clipfrac` 升到 3%–6%，熵明显下降 —— 裁剪这时候才开始起作用。
   这一条把 C2 和 C1 连了起来：**论文的裁剪机制只有在 K > 1 时才有东西可裁**，
   默认 K = 10 不是随手定的。
3. **成本**：K = 10 每个 run 多花约 40% 墙钟（同一 batch 多做 10 倍的 minibatch 更新）。
   在"同样 1M 环境步"的口径下，这是达到高回报要付的代价；如果按墙钟预算比较，
   两者的差距会缩小，但不会消失（K = 1 的 21 分钟只换来 773–1283 的回报）。
4. **跨机器对照（同一配置、不同机器）**：C2 的 K = 10 与 W3 的 `clip0.2` 是同一配置
   （K = 10、clip0.2、1M 步、3 种子），只是主机不同：2247.8 对 1945.0（HalfCheetah，
   +15.6%）、1775.4 对 1430.7（Hopper，+24.1%）、3688.0 对 2297.5（Walker2d，+60.5%）。
   方向一致、幅度差 15%–60%，说明**跨机器的绝对分数漂移可以和要解读的差距同量级**。
   这正是 C2 两个臂坚持同机的原因，也是报告只解读排序、不解读绝对值的证据。
5. **混杂**：`norm_adv` 是 per-minibatch 的，K > 1 时同一批样本每个 epoch 都会用当前
   minibatch 的统计量重新归一化。所以两个臂的差异里同时包含"多走梯度步"和"多归一化"，
   在现有实现里拆不开（见 §5 第 2 条）。

## 5. 局限（必须写进报告）

1. **K = 1 仍然不是"一次梯度步"**：CleanRL 的 batch 是 2,048 步、32 个 minibatch，
   所以 K = 1 也做了 32 次梯度更新。C2 对照的是"同一批数据过几遍"，不是
   "更新几次"。
2. **优势归一化也重复了**：`norm_adv` 是 per-minibatch 的，K > 1 时同一批样本每个
   epoch 都会用当前 minibatch 的统计量重新归一化。因此两个臂的差异里同时包含
   "多走了梯度步"和"多做了归一化"，在现有实现里无法拆开。
3. **K = 10 的每个 epoch 重新打乱 minibatch 顺序**（`np.random.shuffle`），不是把同一
   个 minibatch 重复 10 次。
4. **指标是训练回报**：tail-10 训练回报，不是评估分数；3 个种子只能支撑方向性结论。
5. **墙钟时间受并发影响**：18 次 run 以 9 个进程并行跑在同一台机器上，wall time
   是批内相对成本，不是基准测试。
6. **K = 1 与 K = 10 的预算相同、算力不同**：两者的环境步数都是 1,000,000，但 K = 10
   的梯度计算量是 10 倍。这也正是 C2 要回答的"买到什么、付多少"。

## 6. 复现方式

```powershell
# 18 次矩阵（约 1 小时后完成；9 个进程并行）
python scripts/run_c2.py --jobs 9 --threads 1
# 校验（两臂只允许 update_epochs 不同）
python scripts/verify_runs.py --c2
# 汇总与出图
python scripts/summarize_c2.py        # -> logs/c2_summary.json
python scripts/plot_c2.py             # -> figures/c2_epochs.png, c2_curves.png
python scripts/make_table.py          # -> docs/paper_vs_ours.md（含 C2 表）
```

`logs/c2_summary.json` 由 `scripts/summarize_c2.py` 从这些 CSV 生成；重跑该脚本应得到
逐字节相同的文件（可用 `git status logs/c2_summary.json` 自查）。
